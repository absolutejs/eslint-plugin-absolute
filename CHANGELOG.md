## 0.14.3 — 2026-11-27

### Fixed

- **elysia-composition-boundaries no longer asks for an array form that cannot type-check**

## 0.14.2 — 2026-11-26

### Fixed

- **Rules that use type information declare requiresTypeChecking**
  no-redundant-type-annotation, prefer-drizzle-query-builders and sort-keys-fixable read the TypeScript type checker when the parser provides it, but did not say so. They now declare meta.docs.requiresTypeChecking (typescript-eslint's convention, which also marks rules that still run, with fewer findings, without types), and each description says what is lost without type information. A test now fails if any rule reads the type checker without declaring it.

## 0.13.2 — 2026-11-22

### Fixed

- **no-import-meta-path leaves tool configs alone (an eslint.config's import.meta.dirname)**
  no-import-meta-path no longer flags a development tool's own config (eslint.config.*, prettier.config.*, knip, stylelint, commitlint, lint-staged, tailwind, postcss, vite, vitest, playwright). Those run when the tool does, from where they sit, and are never bundled into the server, so `import.meta.dirname` (say, for typescript-eslint's `tsconfigRootDir`) is right there. The app's `absolute.config.ts` is still checked: the server loads it.
